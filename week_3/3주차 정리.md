
## 인공지능의 진짜 실력을 묻다
### 우리의 목표
- '안 본 문제'를 맞히는 것
- 입력 : 공부시간
- 정답 : 실제 시험점수
- 예측값 : 모델이 예상한 점수
- 인공지능의 진짜 목적은 훈련 데이터의 '암기'가 아니라, 한 번도 보지 못한 새로운 데이터에 대한 '예측'임
### 모델은 무엇을 돌리며 학습하는가? (매개변수)
- #### 라디오 주파수 맞추기 : 매개변수(세타) 조정
	- 학습이란 프로그램이 스스로 코드를 짜는 것이 아님
	- 정확한 소리(정답)가 들릴 때까지, 뇌 속의 수많은 다이얼을 미세하게 돌려 조율하는 과정임
### 잘못된 예측을 어떻게 숫자로 벌주는가? (손실함수)
- #### 오답 노트의 시작 : 오차(Error) 계산
	- 실제 정답과 모델의 예측값의 차이가 오차임
	- 이 오차들을 모아 '얼마나 틀렸는가'를 하나의 숫자로 압축한 것이 손실함수 (Loss Function, L)임
	- 목표 : 이 손실을 최소한으로 줄이는 다이얼 위치를 찾는 것
- #### 평균제곱오차(MSE, 큰 실수에 가혹한 마법의 저울)
	-  MSE = 1/n\*(sigma)(y - y^)^2
	- 왜 제곱을 하는가?
		- +2와 -2의 오차가 0으로 퉁쳐지는 것을 막음
		- 작은 실수보다 '큰 실수'에 훨씬 더 무거운 벌점을 주어, 모델이 큰 오차를 피하도록 강제함
- #### 분류의 손실함수 (틀린 답을 확신할수록 커지는 벌점)
	- 분류에서는 정답을 맞혔는지뿐만 아니라, 얼마나 확신했는지(확률)가 중요함
	- 정답이 1인데 0.1로 예측했다면 엄청난 손실을 부여함 (교차엔트로피 직관)
- #### 경사하강법 (안개 낀 산속에서 하산하기)
	- 현재 위치 : 현재 다이얼(매개변수)의 상태
	- 산의 높이 : 현재의 손실 크기
	- 내려가는 방향 : 손실이 가장 가파르게 줄어드는 방향 (기울기의 반대)
	- 최적화 : 손실함수의 골짜기 바닥을 찾아가는 탐험
- #### 학습률(n)
	- 보폭이 너무 좁음 : 발걸음이 너무 작아 바닥에 도달하기 전 해가 져버림(느린 수렴)
	- 적절한 보폭 : 큼직하고 안정적으로 바닥에 안착 (적절한 학습률)
	- 보폭이 너무 넓음 : 너무 크게 뛰어 반대편 산봉우리로 튕겨 날아감 (발산/불안정)
	- 학습률은 매개변수를 한 번에 얼마나 업데이트할지 결정함
	- 너무 작으면 평생 산을 내려가지 못하고, 너무 크면 산 밖으로 튕겨 나감
- #### 학습의 지휘자 : 누가 모델을 가르치는가
	- 내부 세계
		- 매개변수(Parameter)
		- 학생(모델)이 데이터를 풀며 스스로 깨우치고 변경하는 값
		- model.coef_
	- 외부 세계
		- 하이퍼파라미터(Hyperparameter)
		- 선생님(개발자)이 학습을 시작하기 전에 외부에서 미리 설정하는 지침
		- learning_rate, max_depth
### 왜 문제집과 모의고사를 나누어야 하는가? (데이터 분할)
- #### 3단계 분할
	- 훈련 데이터(Train) - 70%
		- 매일 푸는 문제집
		- 답안지를 보며 오답 노트를 작성하며 매개변수 학습
	- 검증 데이터(Validation) - 15%
		- 9월 모의고사
		- 학습 방향 점검 및 하이퍼파라미터 수정 기회
	- 테스트 데이터(Test) - 15%
		- 봉인된 수능 시험지
		- 실전 단 한 번뿐이며, 결과를 보고 훈련 방식을 절대 되돌릴 수 없음
		- 반드시 마지막 최종 평가를 위해서만 개봉해야 함
- #### 과소적합과 과적합
	- 1차 모형 (과소적합)
		- 학생 : 수업을 전혀 못 따라감
	- 적절한 차수 (일반화)
		- 학생 : 원리 완벽 이해
	- 15차 모형 (과적합)
		- 학생 : 기출문제 번호와 오타까지 외워버림
	- 모델이 훈련 데이터의 '우연한 잡음(Noise)까지 규칙으로 착각하고 암기해 버리면, 정작 새로운 실전 문제에서는 처참하게 무너짐'
### 진짜 실력을 어떤 자(Ruler)로 잴 것인가? (평가지표)
- #### 진짜 실력은 '차이'에서 드러남
	- 훈련 성능은 95%인데 테스트 성능이 68%라면 전형적인 과적합(Overfitting)임
	- 두 성능 간의 격차가 벌어지는 순간을 포착하는 것이 중요함
- #### 회귀 평가
	1. MAE (절댓값 자)
		- 눈금 간격이 일정하며 원래 단위로 해석하기 쉬움
	2. MSE (돋보기 자)
		- 큰 오차 부분의 눈금이 기하급수적으로 벌어짐 (큰 오차에 민감)
	3. RMSE (원상복구 자)
		- MSE로 커진 단위를 원래 스케일로 압축시켜 놓은 실용적인 자
		- 결정계수(R^2) : 평균만 찍었을 때보다 얼마나 똑똑해졌는지를 1에 가깝게 표현
- #### 혼동랭렬 (Confusion Matrix)
	- [[2. 인공지능의 진짜 실력을 묻다.pdf#17]]
	- 분류 문제에서는 단순히 '맞았다/틀렸다'가 아니라, '어떻게 틀렸는가?'를 분석해야 함
- #### 데이터 불균형 (기상청 정확도의 함정)
	- 365일 중 364일이 맑은 사하라 사막 기상청
	- 매일 '비 안 옴'으로 무조건 찍으면 정확도는 99.7%임
	- 하지만 정작 비가 올 때를 한 번도 못 맞춘다면?
	- 이 모델은 쓸모없는 깡통임
- #### 정밀도 vs 재현율
	- 정밀도(Precision) 중요 : 스팸 메일 필터
		- 정상 메일을 차단하면 안 될 때
	- 재현율(Recall) 중요 : 암 환자 진단
		- 환자를 정상으로 오해해 돌려보내면 안 될 때
- #### 복합잔 모델이 항상 정답일까?
	- 다항회귀 차수(degree)를 15까지 늘렸을 때, 훈련 MSE는 바닥을 찍지만 테스트 MSE는 폭발적으로 치솟음
	- 결론 : 다이얼(차수)를 무작정 늘린다고 AI가 똑똑해지는 것이 아님

## 실습 : 모델을 복잡하게 만들면 더 똑똑해질까?
- ### 실습
	- #### 데이터에는 규칙과 잡음이 함께 존재함
		- 관측값 = 규칙 + 잡음
		- 전체적으로는 일정한 패턴이 존재
		- 각 관측값에는 우연한 변동이 포함
		- 잡음까지 학습하면 새로운 데이터에 약해질 수 있음
	- #### 모델의 복잡도 조절
		- Degree = 1
			- 단순한 모델
			- 과소적합 가능
		- Degree = 3
			- 적절한 곡선
			- 패턴을 잘 포착
		- Degree = 15
			- 매우 복잡한 모델
			- 과적합 가능
		- 이번 실험의 하이퍼파라미터 : degree
	- #### 공정하게 실력을 평가하려면
		- 전체 데이터 -> Train data(모델이 보고 학습) -> Test data(보지 않고 평가)
		- Train : 모델의 매개변수를 학습
		- Test : 학습이 끝난 모델의 일반화 성능 확인
		- 이번 실습에서는 원리를 명확히 보기 위해 Train / Test 만 사용
	- #### 첫 번째 실험 : degree만 바꿔보기
		- 모델의 곡선은 어떻게 변하는가?
		- 훈련 데이터를 얼마나 가까이 따라가는가?
		- 지나치게 구불구불해지는 순간은 언제인가?
	- #### 눈으로만 판단하지 않는다
		- MSE로 훈련 데이터와 테스트 데이터의 오차를 각각 측정함
		- MSE = 평균(실제값 - 예측값)^2
		- Train MSE : 학습한 데이터에서의 오차
		- Test MSE : 보지 않은 데이터에서의 오차
	- #### 진짜 실력은 Train과 Test의 차이에서 나타남
		- 훈련 오차가 작다는 사실만으로 좋은 모델이라고 할 수 없음![[스크린샷 2026-10-16 at 22.48.22.png]]
	- #### 모델 복잡도와 일반화
		- 복잡도가 증가하면 Train MSE와 Test MSE는 다르게 움직일 수 있음
- ### 결론
	1. 복잡한 모델이 항상 좋은 모델은 아니다
	2. 훈련 성능이 가장 높은 모델이 항상 좋은 모델은 아니다
	3. 보지 않은 데이터에서도 잘 작동하는 모델이 좋은 모델이다
