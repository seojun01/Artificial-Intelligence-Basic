
## 인공지능은 무엇을 학습하는가?
### 규칙의 한계, 학습의 시작
- #### 전통적 프로그램
	- 사람이 직접 규칙 작성
	- 장점 : 판단 과정이 명확함
	- 한계 : 예외를 모두 미리 작성하기 어려움
- #### 데이터 기반 인공지능
	- 데이터에서 패턴 발견
	- 입력 데이터와 정답의 관계를 알고리즘이 스스로 찾아냄
	- 규칙의 예외가 많을수록, 데이터에서 패턴을 학습하는 AI가 필수적임

### AI 프로젝트의 시작 : 문제 구조화
- 모든 AI 프로젝트는 '인공지능을 만들자'로 끝나지 않음
- **무엇을 입력하고 무엇을 출력할 것인가?** 를 설계하는 것이 시작임
- \[Step 1] 현실 문제
	- ex) 학생의 학업 중단을 예방하고 싶다
- \[Step 2] 데이터
	- 현재까지 수집된 학생의 출석, 성적, 활동 기록
- \[Step 3] 학습 문제
	- 현재까지의 정보를 이용해 (X) -> 다음 학기의 학업 중단 가능성을 예측함 (y)
- #### 좋은 학습 문제를 설계하는 3가지 기둥
	1. 대상 (Target)
		- 누구 또는 무엇을 '하나의 사례'로 볼 것인가?
	2. 시점 (Timing)
		- 언제까지의 정보로, 언제의 결과를 예측하는가?
	3. 출력 (Output)
		- 숫자, 범주, 집단 중 모델이 무엇을 결과로 내놓아야 하는가?
- #### AI를 구성하는 핵심 요소들
	- AI에서 '학습'이란, 입력과 정답의 관계를 이용해 모델이 더 적절한 출력을 내도록 내부 매개변수를 조정하는 과정![[스크린샷 2026-10-14 at 21.51.09.png]]

### 데이터 표의 해부학 : X와 y 구분하기
- 행렬 X (입력 특징, 4건 x 4개 특징)
- 벡터 y (실제 정답, 4개의 정답)
- #### 세상의 모든 데이터는 결국 '숫자(X)가 됨'
	- 텍스트 데이터 -> 단어, 토큰, 임베딩을 거쳐 숫자 벡터로 변환
	- 이미지 데이터 -> 픽셀값의 배열로 변환
	- 오디오 데이터 -> 시간에 따른 신호 파형을 숫자로 변환
	- 핵심 : 겉모습은 달라도 AI 모델에게는 모두 수학적으로 계산 가능한 행렬 X로 입력됨


### 지도학습의 두 갈래 : 회귀와 분류
- #### 지도학습 (Supervised Learning)
	- 입력 X와 정답 y를 함께 제공하여 그 관계를 학습 (핵심 조건 : 학습 데이터에 반드시 정답이 있어야 함)
	- ##### 회귀
		- 연속적인 '수치'를 예측함
		- ex) 내일 최고기온 예측은?
	- ##### 분류
		- 미리 정해진 '범주'를 예측함
		- ex) 대출 부도 여부 판별은?

### 정답이 없거나, 행동으로 배우거나
- #### 비지도학습
	- 정답 y 없이 구조 발견
	- 목표 : 정답 없이 오직 입력 특징만으로 데이터에 숨겨진 패턴을 찾는다
		- 군집화 (비슷한 대상을 묶음)
		- 차원 축소 (핵심 정보만 적은 축으로 요약)
		- 이상치 탐지 (일반적이지 않은 사례 발견)
- #### 강화학습
	- 보상을 통한 행동 최적화
	- 메커니즘 : 상태 -> 행동 -> 환경의 반응 -> 보상
	- 목표 : 정답표 대신 행동의 결과로 받는 '누적 보상'을 최대화하도록 학습
- #### 머신러닝의 학습 유형![[스크린샷 2026-10-14 at 21.57.14.png]]

### 치명적인 설계 함정 : 데이터 누출 (Data Leakage)
- 실제 예측을 수행하는 시점에는 절대 알 수 없는 '미래의 정보'가 학습 데이터에 포함되는 현상
- (모델 성능이 실제보다 비정상적으로 좋아 보이는 착시 유발)
- 데이터 누출의 예시
	- 스팸 실시간 판별 -> 사용자의 사후 신고 여부 포함
	- 학업 중단 예측 -> 자퇴 처리 완료 여부 포함
	- 질병 조기 예측 -> 최종 확진 결과 포함
- 원칙 : 특징은 반드시 실제 예측 시점에 가용해야 함

### 어떤 정보를 입력해야 할까? 4가지 점검 기준
1. 관련성
	- 예측하려는 결과와 논리적 / 통계적 관련이 있는가?
2. 가용성
	- 실제 예측을 수행하는 바로 그 시점에 얻을 수 있는 데이터인가?
3. 측정 가능성
	- 일관된 기준과 방법으로 안정적으로 수집할 수 있는가?
4. 적절성
	- 활용하는데 있어 개인정보보호, 편향, 윤리적 / 법적 문제가 없는가?

### 실전 연습 : 스팸 판별 문제 설계도 완성하기
- 현실 문제 : 스팸 문자를 줄여서 사용자의 불편 해소
- 관측 대상 : 문자 메시지 한 건
- 특징X : 문자 길이, 링크 개수, 특정 단어 포함 여부
- 정답Y : 0(정상) / 1(스팸)
- -> 학습 유형 : 지도 학습 -> 이진 분류
- -> 예측 y^ : 스팸일 확률
- 주의점
	- 데이터 누출 방지 (사후 신고 데이터 배제)
	- 개인정보 보호 (불필요 민감 정보 제거)
	- 편향 방지 (다양한 정상 사례 확보)

### 요약
- 현실의 문제를 인공지능이 이해할 수 있는 수학적 구조(X->y)로 번역해야 함
- 모델의 종류나 알고리즘보다, 관측 대상, 시점, 출력을 정확히 정의하는 것이 먼저임


## 나만의 스마트 스팸 메시지 판별기
### 실습 목표
- 모델을 코딩하는 것이 아니라, AI에게 학습시킬 데이터의 구조를 직접 설계하고 검증하는 것
- #### 번역
	- 현실의 문제(스팸 판별)를 표 구조 X -> y로 번역함
- #### 검증
	- 데이터 누출 컬럼을 직접 넣어 '성능 착시'를 눈으로 확인함
- #### 점검
	- 편향과 개인정보를 체크리스트로 점검하고 마스킹함
### 1. 목표 확인, 데이터 열기
- spam_messages.csv![[스크린샷 2026-10-14 at 22.05.51.png]]
### 2. X, y 매핑 설계
- #### 정답 y - 무엇을 맞히게 할 것인가
	- y = 스팸 여부
		- 1 = 스팸
		- 0 = 정상
	- 라벨링 규칙을 먼저 문장으로
		- "수신자가 원치 않는 일방적 광고, 사기성 메시지면 1, 아니면 0"
		- 애매한 사례를 어디에 둘지 팀이 합의해야 데이터 품질이 유지됨
- #### 특징 X - 메시지를 숫자로 번역
	- 데이터의 문자 길이, 무료포함, 당첨포함, URL 포함, 광고표기, y
### 3. 데이터 누출 시뮬레이션
- #### 함정 : '차단버튼클릭'을 X에 넣으면?
	- 누출 컬럼 포함 : 100%
		- 성능 착시 - 시험지에 정답이 미리 적혀 있던 것
	- 누출 제거 후 : 85.7%
		- 현실적인 성능 - 이것이 진짜 출발점
	- 문자가 도착한 순간에는 '차단 버튼을 눌렀는지'를 알 수 없다 -> 서비스에서는 쓸모없는 모델
- #### 누출 판별 질문 - 셋 중 하나라도 '아니오'면 삭제
	- 시점 : 예측해야 하는 그 순간에 이미 알 수 있는 정보인가?
	- 인과 : 정답이 정해진 뒤에 생겨나는 결과가 아닌가?
	- 재현 : 새 데이터가 들어와도 같은 방식으로 구할 수 있는가?
### 4. 편향, 개인정보 점검
- #### 데이터가 한쪽으로 치우쳐 있지 않은가
	- 클래스 균형
		- 50 : 50
		- 스팸 22건 / 정상 22건
		- 현실은 스팸이 훨씬 적음 - 불균형 데이터에서 '전부 정상'이라 답해도 정확도 95%가 나오는 함정을 주의
	- 유형 편향
		- 우리 스팸이 전부 (광고) 문자 말투라면?
		- -> "검찰청입니다 ..." 같은 보이스피싱형 스팸은 놓치는 모델이 됨
- #### 개인정보 마스킹 - 전화번호를 지우고 학습하기
	- 전 \[Web발신] 축하합니다! 500만원 당첨! 지금 확인 http:// ... 010-2345-6789
	- 후 \[Web발신] 축하합니다! 500만원 당첨! 지금 확인 http:// ... \*\*\*-\*\*\*\*-\*\*\*
### 정리, 과제
1. 주제 선정 (주가 등락, 학업 중단, 배달 시간 예측 등 자유 주제)
2. y 정의 (정답 y가 무엇인지 한 문장으로 정의)
3. X 설계 (특징 컬럼 5개 이상을 표로 설계)
4. 함정 심기 (데이터 누출 컬럼을 일부러 1개 포함하고, 왜 누출인지 설명)
